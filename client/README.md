# ZeroTrustVault — web client

Vite + React 18 + TypeScript (strict). All cryptography runs in the browser with Web Crypto
(`src/crypto/`), byte-compatible with the Python core in `crypto/ztv_crypto` (proved by
`src/test/vectors.test.ts`, whose vectors are generated by the Python reference).

## Run

```sh
cd client
npm install
npm run dev          # http://localhost:5173, proxies /api -> https://localhost:8000 (mTLS cert from ../infra/certs if present)
npm run build        # tsc --noEmit + vite build -> dist/  (what infra/Dockerfile.web runs)
npm test             # vitest cross-implementation vectors (node env; Node 24 webcrypto has Ed25519/X25519)
```

Regenerate the vectors after changing the Python core:
`../.venv/Scripts/python src/test/gen_vectors.py src/test/vectors.json` (run from `crypto/` so `ztv_crypto` imports).

Env (`.env` or build arg): `VITE_ORG_ROOT_PK` = b64u raw Ed25519 org root public key. When unset the client
fetches `/api/keys/org-root` and labels the root **"unpinned (dev)"**. `VITE_HTU_ORIGIN` overrides the origin used
for DPoP `htu` (needed when a proxy rewrites the public origin, e.g. the Vite dev server in front of nginx).

## Security state shown in the UI

Mode (zerotrustvault/baseline), device key present (non-extractable ECDSA P-256 in IndexedDB), session token type,
keys unlocked (Web Crypto non-extractable vs. `@noble/curves` in-memory fallback when the browser lacks
Ed25519/X25519 in `crypto.subtle`), cert status, org-root pinned/unpinned, risk score.

## Scripted fallback (headless / CI)

WebAuthn (`navigator.credentials`) needs a real authenticator or Chrome's virtual authenticator
(`chrome://` DevTools > WebAuthn, or Playwright `cdpSession.send("WebAuthn.enable")` +
`WebAuthn.addVirtualAuthenticator`). Headless runs should use **TOTP** instead (both methods are offered after the
password step; the seed script writes TOTP secrets to `seed/generated/credentials.json`). The Python headless client
(`crypto/ztv_crypto/headless_client.py`) exercises every flow without a browser:
login → TOTP → keys → cert → upload → share → download. The admin "paste" button on the cert-request card simulates
the out-of-band fingerprint confirmation for demos.

## Layout

- `src/crypto/` — encoding, chunks (AES-256-GCM STREAM, AAD), merkle, wrap (X25519→HKDF→AES-KW), sign (Ed25519,
  domain separation, cert verification), keys (Argon2id via hash-wasm, sealed blob), device (IndexedDB CryptoKey),
  dpop (ES256 compact JWS), curves (Web Crypto / noble backend), upload (main-thread streaming encrypt + per-chunk
  DPoP PUT), `worker/decrypt.worker.ts` (streaming verify+decrypt; aborts on first failure and reports the chunk).
- `src/api/client.ts` — DPoP/Bearer fetch wrapper, auto-refresh, step-up prompt, `X-Server-Time` skew.
- `src/pages/` — Login, Enrol (keys/cert/TOTP/passkey), Files (upload/download/share/revoke/rotate), Admin, Dashboard.
